# Auditoria — Camada Frontend (Next.js)

## Visão geral da camada

A camada frontend do `next-app` é um port maduro e disciplinado do app vanilla para Next.js 15 (App Router) + React 19 + TanStack Query v5 + Tailwind v4, com padrão consistente "RSC shell + client component": das **71 páginas**, apenas **3** são client pages inteiras — o resto é um Server Component fino (metadata + `<AppShell><View/></AppShell>`) delegando para um client component colocalizado na pasta da rota. O escopo tem **266 arquivos .ts/.tsx (~49.290 linhas)**, dos quais **186 declaram `use client`**; estado de servidor vive em **50 hooks** (`lib/hooks/`) sobre **50 services** (`lib/services/`), com QueryClient único (staleTime 60s, gcTime 10min, retry 1) e persistência em localStorage com allowlist e cap de 2MB. Os problemas dominantes são de escala de arquivo (5 componentes acima de 1.000 linhas), duplicação massiva nas 4 personas de IA (~4.300 linhas ~70% idênticas), remontagem do AppShell a cada navegação (41 páginas montam o shell individualmente) e vazamento de camada (17 componentes chamando `getSupabase()` direto).

**Números-chave:** 266 arquivos / 49.290 linhas; 186 `use client`; 71 páginas (3 client); 41 páginas montando `<AppShell>`; 1 único `layout.tsx`; 0 `loading.tsx`; 1.016 ocorrências de `style={{` vs 2.694 `className`; 261 `aria-label`; maiores arquivos: QuoteWizard 1.188, WallARView 1.170, ProductDetailSheet 1.134, PostCard 1.040, ProductsList 1.024 linhas.

## Pontos fortes

- **Padrão RSC shell impecavelmente consistente**: página server-side com `metadata` + client view colocalizado, aplicado nas 71 rotas sem exceção relevante. Admin usa `requireAdminServer` no RSC.
- **TanStack Query bem usado**: mutations otimistas canônicas com `cancelQueries` → snapshot → rollback em `onError` → `invalidate` em `onSettled` (`lib/hooks/usePostInteractions.ts:98-126`); `useInfiniteQuery` com cursor ISO (não offset) no feed; queryKeys incluem `user.id` para isolar sessões; hidratação síncrona do cache persistido antes do 1º paint (`components/QueryProvider.tsx:54`).
- **Bibliotecas pesadas fora do bundle inicial**: `three` (`await import('three')` em ArtArWebXR.tsx:91), `jspdf` (`lib/pdf/quotePdf.ts:76`), MediaPipe via WASM remoto, e services de mutação importados sob demanda (`await import('@/lib/services/boost')` no PostCard).
- **AuthProvider defensivo e bem documentado**: timeout de 8s no `getSession()` (WebView pendurado), re-sync em `visibilitychange`/`online`/`pageshow`, `useMemo` no value do context, cookie admin espelhado com dedupe por ref.
- **Persistência de cache com guarda-corpos**: allowlist de prefixos + cap 2MB (`lib/queryPersistence.ts`).
- **Acessibilidade acima da média para app mobile-first**: 261 `aria-label`, `aria-pressed` nos toggles, `role="dialog"`+`aria-modal` nos modais, touch targets 44px explícitos, `prefers-reduced-motion` respeitado no tour, `rel="noopener noreferrer nofollow"` no richText.
- **PT-BR hardcoded consistente** em toda a UI (decisão deliberada, sem mistura de idioma na superfície do usuário).
- **Comentários de arquivo explicando o "porquê"** (histórico de bugs, pegadinhas de WebView/Safari) — raro e valioso.

## Achados

**[ALTO] Duplicação de ~4.300 linhas nas 4 personas de IA — lib/hooks/useSeuZe.ts, useAlice.ts, useFe.ts, useSenna.ts + app/{seu-ze,alice,fe,senna}/*Chat.tsx** — Os 4 hooks (640+532+533+533 = 2.238 linhas) e os 4 componentes de chat (570+526+520+518 = 2.134 linhas) são clones declarados: `useAlice.ts:9-11` diz "clonar em vez de generalizar... quando vier 3ª persona, fazemos o refactor pra config-driven" — e já existem a 3ª e a 4ª. Diff normalizado entre useSeuZe e useAlice mostra ~70% de linhas idênticas (mecânica de thread, VAD, TTS, histórico em localStorage). Qualquer bugfix hoje precisa ser aplicado 4 vezes (o próprio useSeuZe já divergiu +108 linhas dos irmãos). — **Recomendação**: extrair `useAiPersona(config)` + `<AiPersonaChat config>` parametrizados por prefixo de storage, endpoint e voz; a dívida foi reconhecida no código e o gatilho combinado ("3ª persona") já passou.

**[ALTO] AppShell montado por página remonta nav, tour e realtime a cada navegação — components/AppShell.tsx + 41 páginas** — Existe apenas 1 `layout.tsx` (raiz); cada uma das 41 páginas privadas monta seu próprio `<AppShell>`, então toda navegação client-side desmonta e remonta TopNav, BottomNav, AppTour e `RealtimeBindings` (`components/RealtimeBindings.tsx:8` diz "Mount-once em AppShell", mas o shell não é mount-once). Isso re-cria a subscription realtime `global-<userId>` do Supabase (`lib/hooks/useGlobalRealtime.ts:71`) em cada troca de rota — churn de websocket/channel e janela sem eventos durante o re-subscribe — além de perder posição de scroll e re-medir o tour. — **Recomendação**: mover o chrome (TopNav/BottomNav/RealtimeBindings/AppTour) para um layout de grupo de rotas `app/(private)/layout.tsx`, mantendo o gate de auth nele; páginas passam só flags via convenção de rota.

**[ALTO] 5 god components acima de 1.000 linhas com UI + regra de negócio + acesso a dados — app/orcamento-ia/QuoteWizard.tsx (1.188), app/loja/WallARView.tsx (1.170), app/loja/ProductDetailSheet.tsx (1.134), app/feed/PostCard.tsx (1.040), app/loja/ProductsList.tsx (1.024)** — PostCard, por exemplo, concentra 6 responsabilidades num arquivo: card, 4 BottomSheets (opções/denúncia/edição/orçamento), atualização otimista manual do cache do feed (linhas 285-298 e 332-348), insert direto no Supabase e 5 ícones SVG. `app/orcamentos/[id]/page.tsx` é uma página client de 713 linhas. Arquivos nesse tamanho tornam revisão e teste unitário impraticáveis (nenhum deles tem teste de componente). — **Recomendação**: fatiar por sheet/subview (os sub-componentes já existem inline: `PostOptRow`, `ActionButton`, ícones) e extrair as manipulações de cache do feed para um helper único (`feedCache.ts`) — hoje a mesma travessia `pages[].posts[]` está duplicada 3 vezes só dentro do PostCard.

**[ALTO] Catálogo inteiro (~4.000+ produtos) baixado no client — lib/hooks/useProducts.ts:59-61** — O hook pagina via `range` em batches de 1.000 "até pegar todos os ~4000+ produtos", transferindo o catálogo completo a cada visita fria à loja (cache RQ ameniza revisitas, e a allowlist da persistência evita estourar o localStorage, mas o primeiro load móvel paga tudo). A busca/filtro é feita client-side sobre essa massa. — **Recomendação**: mover busca/filtro para o servidor (a infra já existe: FTS `search_all` da Wave 6 e índices) e paginar a listagem por categoria; manter o fetch-all apenas como fallback ou pré-carga em idle.

**[MEDIO] Vazamento de camada: 17 componentes chamam `getSupabase()` direto, incluindo reimplementação de service existente — app/feed/PostCard.tsx:249-263** — O `submitReport` do PostCard faz insert cru na tabela `reports` com cast não-tipado (`sb as unknown as {...}`), enquanto `lib/services/postInteractions.ts` já exporta `reportPost` (importado e exposto por `usePostInteractions.ts:31`). Outros 16 arquivos .tsx (LoginForm, ChatConversation, PublicProfileView, OrcamentoSheet, QualsSection…) também tocam o SDK direto, e 57 componentes importam services sem passar por hook. O contrato "componente → hook → service" existe mas não é aplicado uniformemente. — **Recomendação**: trocar o insert do PostCard por `useReportPost`/`reportPost` e tratar `getSupabase` em componente como lint error (regra `no-restricted-imports` escopada a `app/**` e `components/**`, com exceções nomeadas para auth flows).

**[MEDIO] Modais sem focus trap e sem restauração de foco — components/BottomSheet.tsx, components/Dialog.tsx** — Ambos têm `role="dialog"` + `aria-modal="true"` e fecham por Esc, mas nenhum prende o Tab dentro do modal nem devolve o foco ao elemento de origem ao fechar (o Dialog só autofoca o input do prompt, Dialog.tsx:108-112). Usuário de teclado/leitor de tela tabula para o conteúdo de fundo com sheet aberto. — **Recomendação**: implementar trap de foco (sentinelas ou `inert` no conteúdo de fundo) e restaurar foco no `onClose`, uma vez, nos 2 componentes base.

**[MEDIO] Zero `loading.tsx` e um único `error.tsx` na raiz — app/** — Não existe nenhum `loading.tsx` de rota e só `app/error.tsx` + `global-error.tsx` cobrem erros de render para as 71 páginas. Um throw num client view de rota profunda sobe até o error boundary da raiz, derrubando o chrome inteiro (TopNav/BottomNav somem junto). — **Recomendação**: ao criar o layout de grupo privado, adicionar `error.tsx` nesse nível para o chrome sobreviver a erros de página; `loading.tsx` genérico com o Skeleton existente custa pouco.

**[MEDIO] Componentes mortos no repositório — components/PostActions.tsx (190 linhas), components/NotificationBadge.tsx (29 linhas)** — Nenhum dos dois é importado por arquivo algum. `components/AuthGate.tsx` (95 linhas) é caso distinto: deliberadamente inerte pós-remoção do modo visitante, mas segue importado em 7 arquivos com chamadas `requireAuth('curtir')` que hoje nunca negam — ruído de leitura. — **Recomendação**: deletar PostActions e NotificationBadge; para o AuthGate, decidir — remover as chamadas ou documentar no call-site que é no-op mantido para eventual retorno do guest mode.

**[MEDIO] 1.016 blocos de `style={{}}` competindo com Tailwind — app/feed/PostCard.tsx:364-371 e generalizado** — Proporção ~1 inline style : 2,6 `className`, misturados no mesmo elemento. Consequências: valores mágicos repetidos (borderRadius 18/12/10, fontSize 13.5), impossibilidade de tematizar via tokens (dark mode S13 sobrescreve `var(--color-*)`, mas cores/sombras hardcoded em inline style escapam) e purge do Tailwind sem efeito sobre metade dos estilos. — **Recomendação**: código novo só Tailwind + tokens; extrair padrões repetidos (card, sheet-title, opt-row) quando os god components forem fatiados.

**[BAIXO] Nomenclatura de rotas mistura PT-BR e inglês — app/** — Convivem `perfil`, `publicar`, `orcamentos`, `camisetas` com `feed`, `search`, `explore`, `notes`, `leads`, `checklist`. — **Recomendação**: padronizar PT-BR para rotas novas; sem migração retroativa das já publicadas.

**[BAIXO] Imagens de conteúdo do feed com `alt=""` — app/feed/PostMedia.tsx:160** — Marca a mídia do post como decorativa, mas ela é o conteúdo principal; leitor de tela pula a foto. Mesmo padrão em `app/publicar/MediaPreview.tsx:43` e `components/LeadCard.tsx:64`. — **Recomendação**: usar caption truncada ou `alt={'Foto de ' + nomeDoAutor}`.

**[BAIXO] Cast `as unknown as` para hidratar comments do feed — app/feed/PostCard.tsx:129** — `post.comments as unknown as PostComment[]` é contrato implícito entre `FeedComment` e `PostComment` que o compilador não vigia — se o RPC `get_feed_v2` mudar um campo, quebra silenciosamente em runtime. — **Recomendação**: unificar os dois tipos e rodar `supabase gen types` para eliminar os casts de tabela pendentes.

Nenhum achado CRITICO: sem quebra funcional, XSS (richText escapa e sanitiza corretamente), race condition destrutiva nem regressão de segurança na camada frontend.
